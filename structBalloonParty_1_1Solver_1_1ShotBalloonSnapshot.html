Detailed Description

One board actor as the solver sees it — enough to reproduce pop/deflect/score rules without a live IBalloonModel.

Grown by composition (Shot Solver Accuracy §3): a geometry/scoring core, a ColorProfile, an optional BalanceProfile (null ⇒ no dynamic stub backs this entry — see ShotBoardDynamics's null-Actor gating), a ShotContactKind, and an optional ItemProfile (data-only in this phase — the item layer reads it starting Phase C1). Construct via the named factories, never the (private) field-order constructor directly — that is what keeps every caller's field mapping honest as the struct grows.

A poppable rainbow/wildcard target — mirrors a live balloon whose colour is the reserved GamePalette.RainbowColorId marker (IGamePalette.IsRainbow).

Scoring pays every board-allowed colour (see ShotSimulator.Simulate's allowedColors); the streak rule depends on the shot's own state (wildcard-buffed, colourless-deferred, or colour-anchored) — see ShotSimulator.ResolvePopScore.

A collision-only archetype with no score and no balance-grid presence — Phase A's interactive statics (Deflector/Gatekeeper/Absorber).

Balance is always null: statics never enter the balance grid as movers, so no dynamic stub backs them (see the null-Actor gating in ShotBoardDynamics/ShotSimulator); slotIndex is the actor's REAL grid slot, carried via StaticSlotIndex so a pop/deflect can still address the right cell.

readonly? Vector2Int BalloonParty.Solver.ShotBalloonSnapshot.StaticSlotIndex

The static archetype's own slot — set only by ForStaticContact.

A static never carries a Balance (statics never enter the balance grid as movers), so this is the sole source of slot identity for ShotBalloonState.SlotIndex on a static entry; without it, every static would default to (0,0) and corrupt whatever legitimately occupies that slot on RemoveFromGridAt/OnBalloonHitAt (the 0b-review landmine).
