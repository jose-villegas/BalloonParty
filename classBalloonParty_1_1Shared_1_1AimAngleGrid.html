Detailed Description

The thrower's reachable-angle domain rule: the absolute step grid a quantized aim snaps to, and the sample grid a sweep over an arc uses to visit exactly those angles.

One rule with several independent consumers — the live ThrowerController, the Fire Best Shot cheat, the editor Shot Solver window, and the Scene-view aim fan overlay — so it lives here rather than inside any one of them.

Resolves a raw aim angle into the thrower's reachable set: clamped into [minDegrees , maxDegrees ] and, for a quantized aim (stepDegrees > 0), snapped onto the exact same absolute step grid ResolveSweepAngle sweeps — so the thrower's own clamp and every sweep built on this grid can never disagree about what angles are reachable.

Order matters: clamping the angle and then snapping can push the result back outside the range (the nearest grid line to a clamped boundary sample can sit past it); snapping the angle and then clamping it can land on a value that isn't a step multiple at all. This sidesteps both by clamping the ROUNDED GRID INDEX instead of the angle, so the result is always both a step multiple and inside the range, by construction. Continuous aim (stepDegrees <= 0) is a plain clamp. When no step multiple falls inside the range at all (a step wider than the whole range), falls back to whichever neighbouring grid line sits closest — mirroring ResolveSweepAngle's identical fallback for the same degenerate case. Called directly by ThrowerController.ClampAndQuantizeAimDirection.

The i'th sweep angle over [arcMinDegrees , arcMaxDegrees ], paired with ResolveSweepSampleCount.

Continuous aim (stepDegrees <= 0) lerps evenly across continuousSampleCount samples, exactly as before quantization existed. A quantized aim instead walks the absolute step grid — the same grid ThrowerController.ClampAndQuantizeAimDirection snaps player input to — rather than lerping and hoping the result coincides with a reachable angle. That grid is anchored at multiples of stepDegrees in absolute terms, not at arcMinDegrees , so the first sample is the smallest step multiple at or above arcMinDegrees — not necessarily arcMinDegrees itself. When the step is wider than the whole arc (no multiple falls inside it), this returns whichever neighbouring grid line sits closest to the arc, so the single guaranteed sample from ResolveSweepSampleCount is still a reachable angle.

How many angles a sweep over [arcMinDegrees , arcMaxDegrees ] needs.

Continuous aim (stepDegrees <= 0) keeps the caller's fixed continuousSampleCount unchanged — today's behaviour. A quantized aim instead counts the step multiples that land inside the arc, so the sweep only ever visits angles ThrowerController.ClampAndQuantizeAimDirection can actually reach — a ~31° arc at a 5° step is ~7 samples, not thousands. Always at least 1, even when the step is wider than the whole arc.
