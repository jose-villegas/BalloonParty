SceneCaptureService MonoBehaviour on the persistent camera — a shared low-res capture of the scene's visuals, bound globally as _SceneCaptureTex (resolution divisor from IGameDisplayConfiguration). Any effect that wants "what the screen roughly looks like" acquires it instead of using a GrabPass (a full-screen mid-frame resolve on tile GPUs); the first consumer is the Unbreakable's chrome reflection (UnbreakableBalloonVariant ref-counts via Acquire/Release on enable/disable). Renders only while someone holds an acquire, on a time-based cadence: LateUpdate accumulates Time.unscaledDeltaTime and fires once that accumulator passes \(\text{SceneCaptureFrameInterval} / 60\) seconds — the field is authored as "every Nth frame" but reinterpreted as seconds at a 60 fps reference, so the capture (and the screen-space GI chain it feeds) costs the same on a 120 Hz panel as it does on 60 Hz instead of doubling. Skipped frames keep the previous capture; the accumulator runs unscaled so cadence keeps advancing through pause/slow-mo. The serialized layer mask picks what gets captured — consumers sampling it should exclude their own layer to avoid feedback. The capture camera clears with alpha 0, so the RT's alpha channel doubles as a sprite-coverage mask (ScreenSpaceLightService's occlusion source). The capture RT is allocated with a 24-bit depth buffer even though nothing samples it — URP's RenderGraph rejects a depthless camera output texture ("Fake or uninitialized surface"). The runtime-created capture camera gets a UniversalAdditionalCameraData with post-processing off. One shared mask/resolution on purpose; a second consumer with different needs is the moment to generalize. Its inspector live-previews the capture RT in play mode (SceneCaptureServiceEditor). Registered via RegisterComponentInHierarchy<SceneCaptureService>() in AppLifetimeScope (scope build fails if absent from the persistent camera). Exposes ContentVersion, bumped once per unique capture (stamped at the start of LateUpdate, since a capture camera left enabled last frame rendered during last frame's render phase) — consumers gate rebuild work on it instead of re-deriving the cadence themselves
CameraBackgroundTint [ExecuteAlways] MonoBehaviour on the persistent camera — the scene light's diffuse term for the camera's solid clear colour (the Sprite/Diffuse response applied to the background). Owns the AUTHORED base colour so the multiply can never compound (camera.backgroundColor becomes derived state; Reset() adopts the camera's current colour, so adding it is visually a no-op). Light Influence eases unlit↔fully lit. Reads colour/intensity from ISceneLightRuntime (injected by VContainer) — the live ambient value, which a later night-mode phase can animate at runtime, not just static config. Applied once in OnEnable in play mode; the editor additionally keeps re-applying every Update (guarded to edit mode, i.e. !Application.isPlaying), so inspector tweaks to the base colour, light influence, or the light settings asset still preview live; in edit mode (no DI) falls back to neutral white
ScreenSpaceLightService MonoBehaviour on the persistent camera, next to SceneCaptureService (architecture: Screen-Space Light (2D GI)). Fakes a 2D global + multi-directional indirect light via two low-res blits: Pass 0 is an RSM-style 4-direction VPL gather (shadow = single toward-light march with mip penumbra; bounce = 4 cone marches at 90° spacing around the field's local direction, _SecondaryWeight-modulated). Pass 1 = 3×3 box soften. The smear/work targets run at SmearDownscale below capture resolution (default half — the light buffer is low-frequency, so pass 1's soften doubles as the upsample filter). Composites over the frame as a camera-fitted multiplicative quad. The blit chain only re-runs when SceneCaptureService.ContentVersion has advanced since the last rebuild (or the targets were just resized) — capture-cadence-bound rather than display-refresh-bound, since between refreshes the chain is a pure function of the same capture. All GI tuning lives on SceneLightFieldSettings SO (injected as IScreenSpaceLightSettings); the ambient magnitude reference reads ISceneLightRuntime. DI-registered via RegisterComponentInHierarchy

How it works

GameDisplayConfiguration (in Configuration/) holds a reference world width and height. GetOrthogonalSize() computes the orthographic size that fits both against the current screen aspect (max of fit-width and fit-height), so the play field is fully visible on every device without letterboxing or clipping. Its custom editor previews the resulting size for common device ratios, in the inspector and as a Scene-view overlay.

There is a single persistent camera for the whole session (the Main Camera nested in the app-root prefab, DontDestroyOnLoad) — Launch and Game never had, and now never get, their own camera. The whole camera pipeline above (OrthogonalSizeCameraController, SceneCaptureService, ScreenSpaceLightService, CameraBackgroundTint, CinematicCameraView, CameraShakeView, NavigationCameraReveal) is registered via RegisterComponentInHierarchy<T>() in AppLifetimeScope (Game/) against that one prefab; GameLifetimeScope and LaunchLifetimeScope resolve them from the parent rather than owning their own copies.

URP RenderGraph constraints

The project runs URP's 2D Renderer. Two constraints apply to anyone touching SceneCaptureService or ScreenSpaceLightService:

  • No mid-render-loop Graphics.Blit. RenderPipelineManager.beginCameraRendering looked like the natural port target for the old OnPreRender-driven blit chain, but URP's RenderGraph rejects a Graphics.Blit issued from inside that callback ("EndRenderPass: Not inside a Renderpass"). ScreenSpaceLightService instead drives its two blits from LateUpdate, the same pattern the disturbance field already used — outside the render loop entirely, at the cost of reading the previous frame's capture (see above; it's invisible here).
  • Camera output render textures need a depth buffer. A camera's targetTexture must carry a depth-stencil attachment even if nothing reads depth, or RenderGraph rejects it as a "Fake or uninitialized surface". SceneCaptureService's capture RT is allocated with 24-bit depth for this reason alone — the 2D content underneath never samples it.

Both were discovered porting ScreenSpaceLightService; treat them as defaults for any new camera-to-texture or per-frame blit code in this pipeline, not special cases.
