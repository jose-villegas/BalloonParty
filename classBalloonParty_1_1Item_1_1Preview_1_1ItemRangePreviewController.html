Detailed Description

Decides which item host the aim is sighted on, and drives the one visible range telegraph for it.

Plain C# rather than a component on the balloon prefab, for two reasons. It needs SlotGrid, the item config and the pool — DI singletons that a pooled item visual (hand-threaded by ItemDisplayService, never resolver-spawned) would have to receive one by one. And only ONE preview shows at a time, which is a global arbitration a per-balloon component cannot make without every instance knowing about every other.

PredictionSightProbe is untouched and independent: it drives the per-item visual REACTIONS on the icon itself (glitter, fade, drift). This answers a different question — which single host owns the board-level figure — and shares only the underlying TraceHitGeometry test.
