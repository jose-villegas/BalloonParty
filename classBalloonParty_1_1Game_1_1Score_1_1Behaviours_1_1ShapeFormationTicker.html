Detailed Description

Pooled, zero-allocation per-frame driver for every in-flight shape formation.

Design constraints:

• States, groups and anchors are pooled via swap-remove (mirrors BalloonMotionTicker) — a running formation must never allocate; adding fields to FormationState that reference managed heap objects will defeat this.

• liveTarget re-reads the endpoint centre every tick so a drifting UI bar never leaves the landing position stale — do not cache the target position at launch.

• Transport bridge: every formation in a group shares a single TrailFlight anchor. The flight stays registered (InFlight) through the group's whole life and is unregistered only once the last formation finishes — if a principal that lands first unregistered eagerly, the cinematic would see Idle and snap the remaining shapes mid-travel. Paused inflates ribbon time so the drawn figure survives the freeze; Idle triggers the SnapFade.

• ReportOnce publishes ScoreTrailArrivedMessage SYNCHRONOUSLY (MessagePipe) from both Pass A (Snap) and Pass C (FinishAdvance). A subscriber that re-entrantly triggers a new pop mid-tick (→ BigScoreTrailBehaviour.Begin → LaunchFormation) appends to _states ABOVE the current backward cursor and is simply skipped this tick (picked up next LateTick) — safe only because _pending/_stationary hold object REFERENCES, not indices, and a freshly-launched state's PendingRelease starts false. Don't refactor either list to store indices without re-checking this.
