Detailed Description

Drives the pens of the one visible item-range figure, closed-form off a single clock — no tweens, no coroutines, no per-frame allocation, mirroring ShapeFormationTicker's constraints.

Exactly one figure is ever shown, so this owns a single pen set that Show re-aims rather than a registry of concurrent previews. Arbitration of WHICH host is sighted, and WHAT draws next once a loop cycle completes, both belong to ItemRangePreviewController — this ticker only owns HOW a figure draws and times its own cycle (see CycleComplete).

◆ RequestEarlyCycleEnd()

void BalloonParty.Item.Preview.ItemPreviewTicker.RequestEarlyCycleEnd ( )
package

Ends the current figure's own re-bloom cycle early — the same fade-then-park a full Draw+Hold cycle reaches on its own (see AdvanceRebloomCycle / BeginLoopFade), just triggered before RebloomHoldSeconds would have.

Exists for ItemRangePreviewController's spin-driven re-bloom: a settled rotation must never call Show on a figure that is still visible — that would reposition its pens in place instead of re-blooming them (RefitPens, not AcquirePens) — so it asks the cycle to end here instead and waits for CycleComplete before drawing again, exactly like every other transition. Goes through BeginLoopFade rather than BeginHide deliberately: this figure is expected back very soon, which is what parking (not releasing) means, and is exactly the contract the loop's own scheduled fade already carries — reusing it here means there is still only one route to Park.

Idempotent while a fade — this call's own or the loop's natural one — is already running, and once parked, so the controller can call this every frame a settle remains unconsumed without racing or restarting its own timer.

bool BalloonParty.Item.Preview.ItemPreviewTicker.Show ( IItemRangePreview preview,

Builds preview 's figure for this crossing and aims the pens at it.

Parameters
introduceTrue for a figure's first appearance on this host — pens cascade in one dash at a time: the stroke's own dedicated approach pens draw the leg from the host origin to the stroke's entry point one dash at a time, each retiring the instant its own dash is drawn, then the figure's own dashes cascade from the entry point exactly as before; every dash-slot pen on the stroke waits, parked pen-up, at its own dash's start until its turn, then draws that dash and hands off to the next. False for a re-settle on a host already being telegraphed (the aim nudged but landed on the same host): pens acquired here start already in their settled, post-bloom state, so the figure reappears in place instead of cascading in again. ItemRangePreviewController decides which this is by tracking the slot it last actually showed.
Returns
False when preview 's BuildShape added no stroke for this crossing (a Shield with no wall to brace against, say) — nothing is drawn and the pens already held, if any, are released via Hide rather than left aimed at a host with nothing to show. ItemRangePreviewController reads this to move on to the next sighted host instead of treating an empty figure as a drawn one that ends its cycle.

Called on every aim change while a host stays sighted, so it distinguishes the two cases by ItemPreviewContext.Slot: a DIFFERENT host restarts the pens (they bloom in again from their strokes' entry points), while the SAME host only re-fits the geometry — the figure follows a drifting balloon, or a Shield stub follows the aim tip, without every pen restarting its bloom each time the player nudges the aim. In current play the controller never calls this on a host still actively visible — every call site (a fresh dwell, a sequence advance, and a spin-driven re-bloom via RequestEarlyCycleEnd) only re-Shows once _visible has already dropped first, either via BeginHide (a real hide) or a completed loop cycle parking (see CycleComplete) — so the RefitPens branch below is genuinely a dormant fallback, not exercised by any path today; introduce is the mechanism that actually distinguishes the two cases in practice, independently of whether the geometry itself is acquired or re-fitted.

Carries no colour: every figure draws with the pen prefab's own material, so the telegraph reads as one system and there is no runtime tint path to keep in step with it.
