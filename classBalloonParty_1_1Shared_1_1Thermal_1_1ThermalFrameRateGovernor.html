Detailed Description

Thermal-aware frame-rate governor: walks a rate ladder (e.g.

120 / 80 / 60) so the app settles on a lower but STABLE refresh rate under sustained thermal pressure instead of juddering with half-missed vsyncs at the top rate. Asymmetric hysteresis (fast down, slow up, plus a minimum dwell per rung) prevents oscillation.

Decisions are driven purely by IThermalSource (headroom/status), never by any reported refresh rate, so applying a down-step through FrameRateSettings.ApplyGovernedRate cannot trigger the ARR echo-loop the MatchDisplay vote path guards against.

Time is fed in as accumulated deltas via Advance (called from ITickable.Tick with unscaled delta time) so the state machine has no Time.* dependency and EditMode tests can drive it directly.
